THE GROUNDING GATE, END TO END. The `judge` case submits a resume claiming a
Senior Staff Engineer role at Google, a team of 40, a PhD from Stanford and an
AWS certification, against a base of two annotation jobs at fictional companies.
Five violations, `grounding: fail`, verdict `revise` - and that verdict is
COMPUTED by lib/judge.ts from the report's own evidence, not read from the
model's `verdict` field. atsFormat scored 4 in the same report, which is the
point of rule B2 being a gate: a well-formatted invention is still an invention.

A DEFECT THIS SUITE FOUND IN ITS OWN BRANCH, before any reviewer did. The first
run of the whole path failed on the assertion that the draft must not name
Labelbox or Supervisely. It named both, in a SKILLS line reading "ms office,
google suite, labelbox, supervisely" - the vacancy's keyword list, pasted whole
into a resume grounded in a base that contains none of it. The cause was in this
branch's prompt assembly, not in the model alone: `parsedRequirementsJson`
carried `parsed.keywords`, and a tidy list of skill terms beside an instruction
to use the vacancy's exact spelling is an invitation to reproduce it. Block F's
template asks for "Vacancy requirements"; the keyword list is now out of it, and
the assertion is permanent.
